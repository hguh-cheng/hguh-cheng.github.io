# A Geometric Littlewood–Richardson Rule — interactive Figure 3

An interactive, click-through visualizer of the worked example in Ravi Vakil's
*A Geometric Littlewood–Richardson Rule* (Annals of Mathematics, 2006) —
Figure 3 (with the specialization order of Figure 2), the case
**n = 4, k = 2, α = β = {2, 4}** on the Grassmannian **G(2,4) = 𝔾(1,3)**
of lines in projective 3-space.

You start with the lines meeting **two skew lines**, then let the moving flag M·
drift into the fixed flag F· through a sequence of one-parameter degenerations.
At each step the cycle either stays whole or breaks cleanly into two pieces
(each with multiplicity 1). The single fork here recovers

```
[Ω□] ∪ [Ω□] = [Ω(2)] + [Ω(1,1)]        i.e.   c^(2)_(1),(1) = c^(1,1)_(1),(1) = 1
```

— the lines **through a fixed point** (partition (2), subset {1,4}) and the lines
**contained in a fixed plane** (partition (1,1), subset {2,3}).

Three synchronized views of the same state:

- **Checkerboard** — black checkers encode the relative position of the two flags
  (a permutation σ); white checkers encode the k-plane. The critical row and
  critical diagonal driving the next move are highlighted.
- **Flags in ℙ³** — the moving flag (point ⊂ line ⊂ plane) glides toward the fixed
  flag; the element that moves at each step is highlighted, until M· = F·.
- **Checkergame tree** — the binary tree of the degeneration; each leaf is a
  Schubert variety, and the Littlewood–Richardson coefficient counts the leaves
  of a given type.

Advance with **Next / Prev** (or the arrow keys), jump with the move-dots, pick a
branch at the fork, or press **Play** (spacebar). Everything is self-contained —
no build step and no external JavaScript libraries.

## A note on correctness

The state data in `states.js` was generated by a direct simulation of the rule as
stated in the paper (§2.5–§2.16): white checkers start in configuration ◦_{A,B}
(Prop. 2.7), the black checkers follow the specialization order
σ: 4321 → 4312 → 4132 → 4123 → 1423 → 1243 → 1234, and at each move the white
checkers take the *stay* and/or *swap* options, keeping any result that stays
happy, has no repeated row/column, and preserves the expected dimension
(Lemma 2.6). The simulation yields exactly the two checkergames of Figure 3, with
outputs {1,4} and {2,3} — matching the paper's coefficients.
